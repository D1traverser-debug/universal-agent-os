# Clean-Slate v4 — 冻结需求规格 v1.0

Status: `FROZEN_BASELINE_V1_0 / REQUIREMENTS_AUTHORITY / NO_PRODUCTION_REFACTOR`
Date: 2026-10-13

## 0. 冻结规则

本文件是 clean-slate v4 的需求权威基线。架构、实现、测试和迁移方案必须从本规格推导，不能为了实现方便反向修改需求。

本版本冻结后不再随架构设计自行改动。只有以下情况才允许开新需求版本：
1. 用户明确新增、删除或改变需求；
2. 真实业务/故障证据证明 v1.0 存在遗漏、矛盾或不可验收条款；
3. 外部能力边界变化导致原需求客观不可实现，需要用户重新决策。

任何上述修改都必须新建版本并保留 v1.0，不允许静默覆盖。

规范词：
- **必须**：不满足即 FAIL/BLOCKED；
- **应**：默认必须满足，只有有证据的例外才可降级；
- **可**：可选增强。

# A. 用户意图、要求与作用域治理

| ID | 触发 | 必须行为 | 必留状态/证据 | 失败语义 |
|---|---|---|---|---|
| A01 | 用户发起请求 | 区分新任务、继续、改要求、查询、系统审视/维护、暂停/取消 | intent + target scope | 无法可靠判断时不得串任务；仅在实质歧义时询问 |
| A02 | 新任务 | 解析最终交付物、完成单位、限制、已有长期要求 | goal + constraints + done-condition | 完成条件无法确定且会改变结果时 HOLD |
| A03 | 新增长期/局部要求 | 给要求分配作用域：全局/子系统/任务类型/具体任务/一次性 | requirement id + scope + priority | 作用域不明时不得默认提升为全局 |
| A04 | 新旧要求冲突 | 明确优先级、替代/取消关系 | supersedes/cancelled-by trace | 不得让互斥旧要求继续隐性生效 |
| A05 | 用户撤销/修改要求 | 旧要求进入失效状态并传播到受影响执行计划 | lifecycle state + impacted tasks | 已执行不可逆结果不得伪装为未发生 |
| A06 | 新任务创建 | 与其他任务的 stage/draft/pending/next_action 隔离 | unique task identity | 禁止继承无关业务状态 |
| A07 | “继续/继承” | 恢复明确目标任务及其有效要求 | selected task + recovery evidence | 找不到可靠目标时 BLOCKED，不猜 |
| A08 | 系统审视/维护请求 | 与业务任务执行分离 | maintenance scope | 禁止把系统审视误路由成继续业务 |
| A09 | 用户中途覆盖系统决策 | 允许在授权范围内人工 override，并重算后续依赖/影响 | override reason + affected plan | 不得只改一句结果而留下旧执行链继续跑 |

**验收底线：** “新写文章”“继续文章”“审视写作系统”“以后视频统一角色资产”四类请求不能相互串状态。

# B. 目标驱动的自主任务完成

| ID | 触发 | 必须行为 | 必留状态/证据 | 失败语义 |
|---|---|---|---|---|
| B01 | 任务开始 | 明确真正完成单位 | done-condition | 不能用阶段性成果冒充总任务完成 |
| B02 | 条件充分 | 系统持续自主推进，不把内部步骤推进交给用户 | current plan/stage | 不得每一步无理由等待“继续” |
| B03 | 多阶段任务 | 保持最终目标与局部阶段一致 | goal linkage | 局部优化不得替换最终目标 |
| B04 | 任务执行 | 完成准备→执行→检查→修正→交付闭环 | stage evidence | 只计划/只分发/只尝试不算完成 |
| B05 | 需要用户介入 | 仅限用户独有信息、未授权高影响选择、不可自动裁决冲突、真实能力缺失 | interruption reason | 可自主解决的问题不得甩回用户 |
| B06 | 暂停/窗口将结束 | 在安全点保存可恢复状态 | checkpoint | 没有安全 checkpoint 时不得宣称可无损继续 |
| B07 | 任务完成判断 | 同时满足用户要求、完成条件和必要验证 | completion evidence | 任一关键项未知则不能标 COMPLETE |

| C09 | 当前信息变化快 | 按任务时点重查新鲜度 | freshness evidence | 过期数据不能替代当前数据 |

# D. 执行编排与资源协调

| ID | 触发 | 必须行为 | 必留状态/证据 | 失败语义 |
|---|---|---|---|---|
| D01 | 复杂任务 | 形成足够但不过度的任务图 | work units + dependencies | 过度拆分不得增加无收益协调成本 |
| D02 | 多工作单元 | 识别串行/并行/条件并行、关键路径、等待点和汇合点 | execution graph | 不得危险并发修改同一权威状态 |
| D03 | 执行前 | 确认当前会话/环境真实具备所需 capability | capability handshake | 角色/规则声明不等于真实可执行 |
| D04 | 选择执行方式 | 在 Agent、工具、脚本、模型、provider、connector 等中选择最适配者 | executor binding | 不得为了“多 Agent”增加无效角色 |
| D05 | 有质量/成本/额度约束 | 按质量优先级、成本、额度、时延、可用性、风险路由 | resource decision | 资源不足需降级说明或 BLOCKED，不可静默缩水 |
| D06 | 多执行者 | 明确每个执行者输入、责任、权限、输出、完成条件 | responsibility bindings | 不能多人重复做却无人负责最终结果 |
| D07 | 下游依赖产物 | 确认每个关键输入都有真实 producer 且可到达 consumer | producer→artifact→consumer lineage | 静态死链必须 FAIL |
| D08 | 多 Agent/工具共享上下文 | 只共享完成职责所需信息 | context binding | 禁止无差别灌入全部系统上下文 |
| D09 | 并发执行 | 协调共享状态、重复执行、覆盖、资源争抢和优先级 | concurrency state | 冲突未解决时不得继续发布权威结果 |
| D10 | 多结果汇合 | 做冲突、重复、缺口、一致性检查并仲裁 | merge decision | 简单拼接不算协作完成 |
| D11 | 探索/候选执行 | 与生产权威轨隔离 | lane/status | 未晋升候选不得覆盖生产状态 |
| D12 | runtime/provider/protocol 组合变化 | 重新确认兼容与能力协商 | environment compatibility evidence | 旧组合证据不得自动覆盖新组合 |
| D13 | 用户要求定时/事件触发或闲时维护 | 只有存在真实调度/后台能力时才登记并执行 | scheduler/trigger evidence | 没有后台能力时不得声称会自行运行 |

# E. 系统/子系统拓扑与变更治理

| ID | 触发 | 必须行为 | 必留状态/证据 | 失败语义 |
|---|---|---|---|---|
| E01 | 查询/变更系统 | 能定位系统、子系统、Agent、入口、规则、状态、知识、工作流、验证和依赖 | topology view | 不知道位置时不得先造重复模块 |
| E02 | 核心能力/规则 | 指定主责位置和 owner | authority binding | 同一真值不得多处各自维护 |
| E03 | 增删改查 | 先找到正确层级与作用位置 | target location | 不得默认堆到总控提示词/公共规则 |
| E04 | 修改前 | 理解存在原因、上下游依赖、现实现、重复能力和影响 | impact analysis | 影响未知时高风险修改 HOLD |
| E05 | 系统性变更 | 检查兼容、旧任务、外部依赖和新增失败模式 | change impact | 不得只验证当前症状消失 |
| E06 | 新增/升级/替换子系统 | 管理引入、迁移、替换、停用、删除全生命周期 | lifecycle state | 新机制不能永久叠加成第二套主实现 |
| E07 | 子系统使用公共能力 | 复用连续性、治理、恢复、验证、自进化等通用能力；业务方法留在 owner 内 | ownership boundaries | 中央总控不得吞并所有业务逻辑 |

| E09 | 新实现稳定替代旧实现 | 迁移并退役旧实现 | supersession evidence | 没有退役计划则不能称“简化完成” |
| E10 | 拓扑/执行者/写者数量变化 | 重新评估原并发、一致性和 writer 假设是否仍成立 | topology-change decision | 旧单写者假设不能静默沿用 |

# F. 持久任务状态与跨会话连续性

| ID | 触发 | 必须行为 | 必留状态/证据 | 失败语义 |
|---|---|---|---|---|
| F01 | 长任务运行 | 持久化目标、有效要求、计划、完成/进行/未完成项、决策、证据引用、产物、问题、下一步 | durable task record | 仅聊天记忆不算持久状态 |

| F10 | 摘要/压缩上下文 | 保留未完成义务、授权、工具结果配对、来源、关键状态和恢复语义，并对压缩版本可追踪 | compaction version + retained obligations | 压缩导致义务/来源丢失则 FAIL |

# G. 数据、产物与知识治理

| ID | 触发 | 必须行为 | 必留状态/证据 | 失败语义 |
|---|---|---|---|---|
| G01 | 新对象进入系统 | 分类为权威任务状态、业务数据/快照、生产产物/资产、知识/方法、缓存/镜像、外部参考 | object class | 不同生命周期对象不得混为一种真值 |

| G04 | 时点敏感决策 | 冻结实际使用的数据快照 | snapshot id | 后续更新不能改写当时决策输入 |
| G05 | 关键输出生成 | 建立主要输入→转换→输出血缘 | lineage | 无法追溯关键输入时保证等级降低 |
| G06 | 输入缺失/冲突 | reconciliation、明确降级或阻断结论 | completeness/conflict status | 不得以部分输入冒充完整结果 |
| G07 | 跨镜头/阶段资产 | 管理角色/场景/道具/模板身份、批准版本和连续性 | approved asset refs | 未批准漂移不得进入生产 |
| G08 | 交付文件/视频/表格 | 验证用户当前可获得的产物就是被验收版本 | deliverable identity + visibility proof | 仅有历史 hash/路径不算交付成功 |
| G09 | 候选知识 | 记录作用域、证据等级、晋升/退役状态 | knowledge lifecycle | 单案例不得直接变正式公共规则 |
| G10 | 清理旧数据/缓存/资产 | 先确认活动任务、审计、回溯和迁移依赖 | retention decision | 被引用对象不得无检查删除 |

# H. 运行监测、故障诊断与可靠恢复

| ID | 触发 | 必须行为 | 必留状态/证据 | 失败语义 |
|---|---|---|---|---|
| H01 | 执行中 | 监测结果偏差、工具/Agent 异常、数据冲突、要求违反、状态不一致、未知结果 | fault signal | 严重异常不能一路传播 |
| H02 | 关键异常 | 阻断依赖错误结果的后续步骤 | hold/isolation state | 不得“先跑完再说”扩大损害 |
| H03 | 故障诊断 | 区分任务、数据、工具/provider、Agent/子系统、公共机制、架构层问题 | fault class | 只修表面症状不算根因关闭 |
| H04 | 外部副作用结果未知 | 先查询实际结果，再决定重试/补偿 | outcome reconciliation | 禁止盲重试造成重复副作用 |
| H05 | 需要重试 | 有 retry owner、上限、幂等/去重或补偿策略 | retry record | 无上限重试 FAIL |
| H06 | 局部故障 | 尽量隔离；必要时降级或安全停止，并明确能力损失 | degraded mode | 降级后不能继续宣称原保证等级 |
| H07 | 高影响路径 | 考虑选定的多故障组合，而非只测单故障 | multi-fault scenarios | 已知关键组合未覆盖时标 assurance gap |
| H08 | 当前机制无法解决 | 主动研究成熟方案并比较适配性 | research/decision evidence | 不得只记录“以后注意” |
| H09 | 修复完成 | 验证原故障、回归影响、新故障和临时补丁 | recovery verification | 没有回归证据不能关闭系统性故障 |

# I. 自我进化、主动维护与复杂度控制

| ID | 触发 | 必须行为 | 必留状态/证据 | 失败语义 |
|---|---|---|---|---|
| I01 | 用户纠正/失败/返工/漂移/新技术 | 形成改进候选而非直接生产变更 | candidate id | 候选不得自动晋升 |
| I02 | 重复/相似失败 | 聚类共同失败类并找正确抽象层 | failure-class mapping | 不得每个案例单独永久加规则 |
| I03 | 缺可靠方案 | 主动检索/学习/比较替代方案 | alternatives | 没有证据不得宣称最佳 |
| I04 | 候选方案 | 明确解决什么、适用范围、新风险、成本 | candidate assessment | 无边界候选不得推广 |
| I05 | 晋升前 | 用可复现 eval/回归或真实证据证明改善 | promotion evidence | 无改进证据不得正式采用 |
| I06 | 晋升后 | 监测效果，支持回滚、替换、退役旧机制 | lifecycle trace | 新旧主实现永久并存 FAIL |
| I07 | 局部优化 | 检查其他功能、单点、维护负担和风险转移 | global impact | 拆东墙补西墙 FAIL |
| I08 | 新增非平凡机制 | 说明新增能力、无法复用原因、复杂度/上下文/工具/运维成本、能删什么 | complexity budget | 只加不删且收益不明不得晋升 |
| I09 | 有真实后台能力且空闲 | 主动检查父/子系统隐患、重复、漂移、过时知识和长期问题 | scheduled/triggered maintenance evidence | 没有调度能力不得声称会自动运行 |
| I10 | 主动维护 | 不抢高优先业务、不擅改已确认业务结果、不把高风险重构伪装清理 | maintenance priority | 冲突时前台业务/用户授权优先 |

# J. 质量验证、完成证明与用户交付

| ID | 触发 | 必须行为 | 必留状态/证据 | 失败语义 |
|---|---|---|---|---|
| J01 | 交付前 | 逐项回查当前有效用户要求 | requirement→result trace | 关键要求无结果则不能 COMPLETE |
| J02 | 验证 | 验证真实结果/行为/文件，而不是流程文件或角色自称 | verification evidence | “规则存在/Agent说做了”不算 PASS |
| J03 | 可交付物 | 确认被验收版本就是用户当前收到/可访问版本 | delivery proof | 错版本/不可访问 FAIL |
| J04 | 高风险/高质量任务 | 尽量用与生产不同的验证机制、证据源或 reviewer 边界 | independence evidence | 同一路径自证时降低 assurance |
| J05 | 系统质量 | 按能力/失败类/不变量报告覆盖，而不是原始测试数量 | coverage map | test count 不能替代能力证明 |
| J06 | 关键执行步骤 | 只有实际研究、审核、调用、修改、发布发生并有证据时才能宣称完成 | execution receipt/trace | 角色扮演式“已审核” FAIL |
| J07 | 状态汇报 | 明确 COMPLETE / VERIFIED / PARTIAL / UNVERIFIED / BLOCKED / UNKNOWN | status | 不得把计划/尝试写成完成 |
| J08 | 最终答复 | 先给用户结果，再说明关键过程、决策、资料、修改、检查和剩余风险 | delivery summary | 流水账不能替代结果 |
| J09 | 结束/暂停 | 确保 F 层可恢复状态已落账 | checkpoint ref | 最终聊天文本不能是唯一记录 |

# X. 跨域约束

| ID | 约束 |
|---|---|
| X01 | 用户负担最小：用户主要给目标、改要求和做人类必须的决策，内部管理不甩给用户。 |
| X02 | 不臃肿：优先复用、合并、替换、删除；文件/规则/Agent/测试数量增加本身不是进步。 |
| X03 | 不拆东墙补西墙：修复必须评估全局影响。 |
| X04 | 真值与证据等级可辨：权威状态、数据、产物、缓存、历史、候选知识、推断、参考必须可区分。 |
| X05 | 自主受授权边界约束：高影响、不可逆、权限外操作遵守授权/HITL；批准必须绑定具体动作、对象、参数/版本和有效期。 |
| X06 | 故障与作用域隔离：任务、子系统、实验的错误/状态不无故污染其他域。 |
| X07 | 兼容与迁移显式：升级后明确直接兼容、迁移或不兼容。 |
| X08 | 成本与收益成比例：考虑时间、上下文、模型额度、外部费用、工具调用、维护和人工 toil。 |
| X09 | 可追溯：要求、输入、决策、执行、变更、产物、验证之间可追溯。 |
| X10 | 禁止虚假完成：计划、规则、角色、测试文件、Agent 自称都不自动证明完成。 |
| X11 | 高影响不变量优先机械化：能用权限、schema、状态机、CAS/transaction、runtime gate 等阻止非法动作时，不只依赖提示语；做不到必须降低保证等级。 |
| X12 | 关键前置缺失不得静默降级：缺关键数据、能力、授权、证据时阻断或明确降级。 |
| X13 | 探索/候选与权威生产分离：未验证候选不得污染生产真值。 |
| X14 | 最小权限与秘密隔离：Agent/工具只获得完成职责需要的访问权；凭据/秘密不得进入普通知识或无关上下文。 |
| X15 | 可观察但不以观察替代真值：监控/信号可触发检查，不能未经验证直接修改权威状态。 |

# Y. 冻结验收场景

以下场景共同覆盖 A–J；通过它们不等于所有实现自动 PASS，但任何最终架构必须能给出对应验收证据。

1. 普通“做 XX”：自主完成闭环，不让用户管理内部流程。
2. 财经新文章：新任务隔离、当前研究、真实流程执行、当前交付 Word 验真。
3. 财经系统审视：不误接为文章续写；变更落到正确系统层。
4. A 股盘前：关键数据完整、冻结、血缘、依赖门禁；缺关键输入不荐股。
5. A 股盘后：真实结果和五池等输入冻结；与盘前判断可追溯；单日经验不直接晋升。
6. 视频多 Agent：角色/场景资产连续；producer→artifact→consumer 可达；模型/工具按镜头路由；真实审核证据。
7. 小说整本蒸馏并原创：整本为完成单位；coverage/next-location 可恢复；单书规律不泛化；蒸馏知识实际用于原创。
8. 聊天上限后“继承”：精确恢复真实任务、对象、要求和下一步，不重述、不串任务。
9. 用户新增/撤销长期要求：作用域、冲突、替代、传播正确。
10. 工具超时且外部结果未知：先查副作用，再重试/补偿。
11. 子系统同类故障反复：提升为共同失败类，修正确抽象层并回归验证。
12. 多任务/多 Agent 并发竞争：优先级、状态冲突、资源竞争安全协调。
13. 新 Agent/模型/工具引入：先证明需要、兼容、成本、位置、权限和旧机制退出计划。
14. 系统升级后继续旧任务：兼容/迁移/阻塞明确。
15. 当前文件/产物交付：状态记录不能代替当前可访问的正确文件。
16. 空闲维护：只有真实后台能力/授权时才运行；不抢前台业务。
17. 上下文压缩后恢复：未完成义务、审批、tool/result、来源、next_action 不丢。
18. 两个故障同时发生：关键路径至少覆盖选定并发故障组合。
19. 用户中途改目标：停止/重算受影响工作，未受影响成果可复用。
20. 权限不足：系统明确 BLOCKED/请求授权，不能用低权限替代路径偷偷完成高权限目标。

# Z. v1.0 完成/冻结判定

v1.0 冻结的理由：

1. 五类真实业务反推未再发现无法归入 A–J 的独立一级能力；
2. 最后一轮横向压力覆盖了并发、要求变更、跨窗口、部分失败、未知副作用、数据冲突、provider/runtime 变化、系统升级、父子系统变更、后台维护、成本竞争、权限/HITL、上下文压缩和多故障；
3. 当前 18 个控制面功能域和已知 G01–G30 风险均可映射到 A–J/X，不需要额外顶层能力；
4. 每个一级能力的关键行为已具备触发、必须行为、状态/证据和失败语义；
5. 后续架构设计不得新增“为架构服务的伪需求”，只能证明如何满足本规格。

**结论：`REQUIREMENTS_FROZEN_V1_0`。**

当前冻结只表示“需求基线稳定并停止主动修改”，不表示生产架构已实现或可靠性缺口已关闭。material-main 机械写入防护仍是独立 OPEN/BLOCKED 实现问题。
