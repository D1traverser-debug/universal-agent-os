# 03｜认知、深度学习、方法归纳、知识蒸馏与迁移：专题知识库

日期：2026-10-19；来源：外部原始学术文献、研究代码、Anthropic 工程资料及 UAOS 既有 `problem_space.py` / `knowledge.py` / `08_operational_method_transfer_taxonomy.md`。归属已有总控 Evolution，不增加知识生命周期权威。以下“学习”是可读取/调用的经验及方法学习，**不**是更新基础模型参数。

## 1. 学习的对象并非网页，而是事实、因果与可迁移的方法

一篇论文至少需要分离：研究任务及作者自设条件、技术机制、训练/评价信号、原始实验、失效范围、工程前提、竞争方法、UAOS 迁移对象、未验证的假设。仅收藏链接不是学习；仅看摘要不是全文掌握；仅存经验不等于回忆时适用；仅在原训练任务成功不等于跨任务迁移。

## 2. 原始研究逐项

### C01 — Reflexion (2023)
原文：https://arxiv.org/abs/2303.11366
- 机制：Agent 从环境反馈生成语言层反思，写入 episodic memory，后续任务以反思辅助决策；不是模型权重更新。
- 实验价值：反馈来源包括执行结果，也可包含模型内部模拟反馈；不同反馈来源可信程度不同。
- UAOS 迁移：一次“错误声称完成→独立反例”成为带来源的失败经验；不能靠模型内省自证因果。
- 风险：反思可能是合理化故事，未经工具结果反证不能升为 canonical method。

### C02 — ExpeL (2024)
原始研究项目：https://andrewzh112.github.io/expel/
- 机制：尝试多任务，利用成功与失败轨迹归纳一般洞察，用成功案例支持后续任务；尤其区分具体动作与可迁移 insight。
- UAOS 实例：从多个“工具受阻—继续其他工作”的不同领域轨迹概括触发条件，而不是把用户纠正文本原封存档。
- 失效：网站任务的成功/失败信号可能比财经产品价值判据明确；不能直接将网络导航回报当业务判断准则。

### C03 — Agent Workflow Memory (AWM, 2024)
论文：https://arxiv.org/abs/2409.07429
- 机制：从交互轨迹抽取可重用的参数化工作程序，支持线上线下归纳和选择性调用。
- 核心不是“每次装入所有流程”，而是“按目标与上下文选择可能有用的程序”。
- UAOS 可复用：已有 KnowledgeItem/MethodTransferAssessment；不要新建一套 workflow memory 主仓。
- 风险：脱离领域权威的泛化程序可能越权写资产或破坏业务状态，必须有非适用条件。

### C04 — Experiential Reflective Learning, 2026
论文：https://arxiv.org/abs/2603.24639
- 机制：反思任务轨迹/结果，提取带条件的 heuristics，针对新任务检索；论文消融强调选择性检索优于无选择地堆叠经验。
- 核心启示：知识**检索质量**比知识数量更重要。全量持久知识库可以存在，但每轮执行并不应把原文全量塞入上下文。
- 性能声明仅属于原论文 Gaia2 设定，不把其基准涨幅视作 UAOS 的实测效益。
- UAOS 测试：给出一个表面相似却在不同宿主安全边界下不适用的方法，正确行为为“检索到，但拒绝调用”。

### C05 — Trace2Skill: trajectory-local distillation
研究代码：https://github.com/Qwen-Applications/Trace2Skill
- 机制：从多个执行轨迹提出局部候选技能修改，再把相互冲突、重复的补丁层次化合并成一致的技能目录。
- UAOS 可迁移：不要将一个失败样本直接变成全局规则；跨案例聚类失败类别，区分新增、替换、删除，验证冲突和结果。
- 风险：论文/工程源中的并行代理设计不自动适用于本仓；无理由增加第二个技能仓库或新模型预算。

### C06 — Lost in the Middle，TACL 2024
原文：https://aclanthology.org/2024.tacl-1.9/
- 实验：长上下文中关键事实位置影响检索与推理，输入越多并不保证可靠使用。
- UAOS 影响：即使用户要求详尽学习，也要**完整保存研究资料与按需提供精准证据**，避免把每个专题全文固定注入所有回合；不能将“读入更多 token”当成更广阔知识。
- 非适用：该论文涉及当时评测模型/任务，不能直接断言当前模型在所有情境都发生相同幅度退化。

### C07 — Effective Context Engineering, 2025
工程原文：https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
- 描述：上下文是有限资源，Agent 应持续优化每一轮加载的高信噪比信息；含工具、消息历史、外部知识、检索产物。
- UAOS 对照：原来父任务 45K 字符上限、GitHub 热路径压缩是容量约束；现在新增知识库应该在冷路径索引检索，不把全部知识复制进入任务状态。
- 限制：Anthropic 自家实践是经验来源，不能不经 UAOS 真实试验认定最佳。

### C08 — Long-running agent harness, 2025/2026
原文：https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents
- 机制：跨上下文会话的可恢复任务计划、明确状态和交接文件，使下一次能够在当前工作基础上继续。
- 启发：持久任务状态是延续的必要条件之一，但有状态≠有实际自动运行；宿主需触发、调用和观察效果。
- 风险：照搬多代理方案易造成重复控制权；只吸收明确收据和环境复原的机制。

## 3. 完整知识蒸馏流程：source → finding → mechanism → candidate → holdout → reuse

1. **收集**：原始资料/论文/运行轨迹 + 来源版本、时间、对象、许可/访问条件。
2. **校验**：区分来源事实、作者推断、基准结果、Agent 分析、自述及未知。
3. **分解**：识别问题类型、触发因素、操作步骤、环境依赖、反例、输出效果。
4. **聚类**：相似策略合并，冲突策略对照；不要仅按名称聚类，“监控”与“自我治理”不同。
5. **反事实**：无此方法是否能解决？错用会怎样？换宿主/领域能否继续？
6. **提炼**：形成小型方法卡：名称、目的、trigger、required facts、algorithm、nonfit、tool roles、expected result、rollback、verification。
7. **试用**：在未参与蒸馏的新任务里检索方法并执行，对比基线。
8. **观察**：保存失败/副作用；按 owner 生命周期升级、修订、淘汰。

方法卡不是新的 SOP：认知策略提供选择条件；SOP 提供具体动作序列。方法可选择多个工作流实现，“条条大路通罗马”仍受目标、权限和效果约束。

## 4. 关键失败类别与对应研究反证

- **文档即知识的错觉**：论文被摘抄并合并，但从未在新任务中触发适用方法。验收：检索日志+真实任务结果。
- **反思等于真相的错觉**：模型称“根因是条件 if”，未比较宿主是否真实运行。验收：竞争因果模型+工具证据。
- **更多经验更好**：旧经验大量占据上下文，新任务有误引用/过时。验收：精准检索 vs 大段全量加载，对比正确率、耗时。
- **同名不代表同解**：不同业务“暂停”有合法用户等待、外部依赖和异常停工；用错经验会引起乱操作。
- **错误方法永不退役**：验证失败却保留 canonical 状态。验收：包含 rollback/revision 的知识生命周期。
- **只学一个行业**：股票、小说、视频、工程不同的专业权威各归其业务仓，父仓可综合共性但不能复制业务领域权威。

## 5. 可执行而可反证的蒸馏范例

输入轨迹 T1：工具拒绝 PR 创建，Agent 立即报告“不能继续”；仍有授权的只读文献检索/项目文件读取；人工提醒后发生进一步实际动作。
候选方法 K：收到单操作拒绝时，先重新求值 remaining-work graph；若有不依赖被拒动作的授权节点，执行并验证；保持拒绝动作不可绕行。
竞争解释：只是环境缺少权限、宿主不具备触发能力、任务本来已完结、用户特定要求只执行这个动作。
必要反事实：若 GitHub 写入被安全拒绝，其他云服务仍能写同一资产，则不得绕行；若只读知识学习独立可做，则应继续。
保留状态：`CANDIDATE`；等至少一个陌生子域、一个真正用户审批阻断、一个超时 UNKNOWN 序列的真实执行收据和结果对照。
归属：现有 `EVO-20261018-INHERITANCE-REVIEW` / `KnowledgeItem`，不在论文库中擅自宣称 CANONICAL。

## 6. 知识库与推理热路径分离

- 冷路径：本文件及其他主题原始方法卡，保留来源、对照和未知；详细、可持续累积。
- 温路径：按目标/问题类别/环境/失败模式检索方法候选；包含来源、适用/非适用、最新失效点。
- 热路径：选中的几条方法和当前事实、行动计划、进度；无需复制几十页知识。若用户要求全部研究，可以公开完整冷路径资料，但执行仍需按事实挑选方法。
- 业务内容属于四个子仓；父库只保留通用方法或指向子仓来源的受控链接。

## 7. 当前完整度与继续条件

来源角色覆盖：原始学术文献、实证评测、研究开源代码、工程作者实践、既有仓库方法。尚无 UAOS 独立 holdout 成功样本、当前原生跨轮认知轨迹和模型参数更新证据；不宣称“已掌握”“实际蒸馏可迁移知识”。
下一轮知识更新优先研究不同模型/权限/业务上**错用经验**的失败样本，和来源结论冲突的新方法，而不是盲目增加论文数量。
