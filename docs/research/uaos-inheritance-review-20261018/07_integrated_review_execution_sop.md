# Evidence-driven UAOS controller review SOP (derived candidate, non-authoritative)
Status: **CANDIDATE OPERATIONAL GUIDE**. Sources: see `06_multicausal_autonomy_method_comparison.md`.
Owners: `state/TASK_INDEX.json` (continuity), `config/SESSION_INTERACTION_POLICY.json` (routing), existing CognitionCase/DeepTask/KnowledgeAcquisitionAdmission (thinking/research), existing ActionCoordinator (mutation), existing EvolutionTransaction (durable change). NO new independent lifecycle.

## Entry & continuation
1. On every substantive UAOS controller operation, recover current objective, exact controller state and latest repo heads. Resolve authority before reusing a chat conclusion. Resume incomplete prior research/repair before accepting an unrelated easy subtask as a substitute.
2. Inventory all currently registered repositories and six critical control dimensions. Every cell is SOURCE_IDENTIFIED, VERIFIED, FAILED, UNKNOWN or BLOCKED with head, code/path and scenario; mere found files do not count as DEEP_VERIFIED. Maintain a gap queue and explicit next-action receipt in the **existing** task.
3. Recheck your own earliest conclusion against at least four causal lenses: user-visible symptom, local implementation, architecture/requirements/control boundary, external host/environment/organizational or workflow factors. For material cases include simultaneous causal factors, rival hypotheses, counterfactuals and independent evidence, not a single root-label.

## Independent research modules
4. For each material unknown, define objective and source-role plan FIRST, then investigate in separate modules:
   - Requirements/change propagation: NASA; derived requirement ownership, bidirectional trace, impact graph and post-action downstream consistency.
   - Causality/safety: MIT CAST/STPA; control-structure failure and interacting factors, alternatives and falsifiers.
   - Architecture: SEI ATAM/holistic; business-quality scenarios, tradeoffs, shadow owners, no-change baseline and review after release.
   - Management/change learning: NIST AI RMF, ASQ PDCA; accountable decisions, current risks and actual monitored effects.
   - Operations/autonomy: Google SRE and IBM MAPE-K; observable trigger/effector/feedback and no human-as-monitor assumptions.
   - Agent evaluation: OpenAI trace/graders; real steps, tools, handoffs and failures; independent cross-session or controlled environment evidence.
   Independent means distinct assumptions/methods/source failure modes; repeating two pages from the same vendor is not independent validation.
5. For each module persist: exact reference URL/commit, source role, what it actually asserts, failure mode it addresses, limitations, comparison candidates, evidence contradiction, current UAOS owner or NEW_GAP, and at least one testable scenario. Run query/reference/repository/adjacent expansion; **do not claim saturation** until two genuinely distinct terminal expansion passes yield no material new method family/failure condition/constraint and the research admission accepts evidence. Unknown means OPEN, not passed.

## Decisions & action chain
6. Build the evidence graph for *admitted* requirement and derived constraints -> owner -> actions -> work roots/dependencies -> changed assets -> tests and business V&V -> post-action emerging requirements and failure modes. Compare DO_NOTHING, owner-local fix and systemic redesign against independent counterexamples and architecture tradeoffs. Choose the smallest COMPLETE intervention, not merely the smallest diff, and do not automatically classify a task change as durable evolution.
7. Before permitted mutation run owner authority/approval and risk checks; for cross-domain work retain child business authority and review applicable owner tests. Use canonical EvolutionTransaction ONLY when admitted; an unresolved cognitive or research gap is work to continue, not a reason to stop at a recommendation.

## Observe, learn, resume
8. After each material action, reread actual state and check: Did desired behavior change? Did any other factor stay active? Did this induce a new requirement/conflict? Did another owner drift? Did prior fix violate a quality goal? Record failed and rejected paths. If actionable work remains and tools permit it, continue immediately without waiting for the user's next correction.
9. Final report: distinguish repository CI, independent research admission, domain business outcome, native-host actuation, and unobserved unknowns. When work is incomplete, keep exact resumable task RUNNING with pinned next step and reason. Finish only when matched objective, cross-factor observations and all declared acceptance evidence pass.

## Stop and trigger test
- Positive: independent native UAOS inheritance work starts this process without a user correction; recovered task produces tool traces/action and fresh current-head evidence.
- Negative: selected-context turn only says CI green; missing deep role evidence; stale heads; a guessed root; two simultaneous causes; schema/owner drift; user tries to impose a fix as root cause; synthetic test is presented as live production.
- Distinguish a *real external blocker* (permission, required choice, unavailable real host trace) from internal research, testing and permitted repair the Agent itself can perform.
- **No synthetic test and no document, including this SOP, can prove native ChatGPT always runs the process.** Native proof needs externally observable selected-session execution.
