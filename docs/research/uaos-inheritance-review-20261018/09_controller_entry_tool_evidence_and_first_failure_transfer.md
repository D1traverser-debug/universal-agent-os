# Controller entry and first-failure method-transfer refinement (2026-10-18)

Scope: **UAOS controller only**. Status: **CANDIDATE SOURCE-PROVEN ADMISSION CHANGE — NATIVE CHATGPT ASSURANCE OPEN**. This extends the existing eight-family taxonomy in `08_operational_method_transfer_taxonomy.md` and existing CognitionCase/Deep Task/EvolutionTransaction, not a new method owner.

## Direct code evidence and fault tree

1. `src/uaos/runtime/epistemic_entry.py#_FACT_KINDS` accepted REPOSITORY_FACT, TEST_RESULT and RUNTIME_OBSERVATION, but excluded TOOL_RESULT. Therefore a trusted GitHub/CI connector result classifying SYSTEM_OR_RULE_CONTRADICTION or MATERIAL_KNOWLEDGE_GAP produced **no problem/deep-learning route** even if its host attribution passed. An entry reporting clean/no material issue could then reach the controlled finalization path while the tool-established problem remained unclassified.
2. `src/uaos/kernel/cognition_case.py#require_cognition_case_admission` required historical method evaluation only at `repeated_failure_count >= 2`. An initial serious material architecture/control failure could satisfy all other causal tests without investigating already-promoted method families; the user had to complain twice to activate method transfer.
3. `config/SESSION_INTERACTION_POLICY.json#mandatory_selected_context_entry.checks` already required general self-challenge and contextual research, but did **not explicitly bind source-grounded historical method fit vs nonfit** into the selected-context entry. The generated Skill inherits these checks and has no own authority; enriching only Skill prose would diverge from canonical policy.

## Alternative causal explanations and choice

- **A. Missing global thinking instructions:** rejected as sole explanation: `DELIBERATION_POLICY`, knowledge and evolution gates already exist, and a provider tool-fact omission is executable source code rather than a prose shortage.
- **B. The native ChatGPT Skill is sometimes not invoked:** material open factor; no repository Python patch or CI can guarantee product-level pre-send interception. Retain `NATIVE_TRACE_UNVERIFIED` until independently observed.
- **C. The entry's typed evidence allowlist and material-first method activation are incomplete:** directly supported by source and negative replay; chosen bounded intervention.
- **D. Copy full cognition inside each child:** rejected for duplicate owner and drift; no child repo writes in this controller-priority task.

## Bounded implementation

- Expand `_FACT_KINDS` by `EvidenceKind.TOOL_RESULT`, requiring the existing independent host `entry_evidence_verifier` to verify observation reference. **Keep** `ANALYSIS_RESULT`, `SCENARIO_RESULT`, `USER_CLAIM` out of this fact allowlist to avoid self-certifying synthetic thought or prose.
- Expand method transfer requirement beyond repeated failures to the **first** `material_problem` where `architecture_gap`, `cross_subsystem` or `unknown_failure_class` is true. This uses the existing current `KnowledgeItem` lifecycle and `MethodTransferAssessment`; no actual prior method may be selected without a trusted catalog resolver.
- In the canonical selected-context entry and its non-authoritative Skill/runtime profile projections, recall applicable method families and probe nonfit before a systemic response. Maintain a lightweight path for isolated small local faults.
- Evidence does not become proof merely because its type says `TOOL_RESULT`; all entry references still require a genuine **host verifier**; tool content is not source authority by itself. Entry cannot validate provider identity alone.
