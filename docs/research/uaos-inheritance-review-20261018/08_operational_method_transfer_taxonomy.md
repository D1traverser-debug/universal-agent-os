## Actual question and fault tree

The observed failure is not merely forgetting a recent user preference. A controller with extensive rules, five-repo audit history, a cognition gate and CI still needed repeated user interventions to: (a) expand the problem space, (b) recognize a formerly solved failure *class* inside a new domain, (c) learn outside methods deeply rather than cite them, (d) select a complete intervention, and (e) continue to actual outcome.

Separate failure routes (not alternatives forced into one root):
- **Entry/invocation:** native ChatGPT may not invoke installed non-authoritative Skill or controlled finalization; actual trace inaccessible.
- **Authority/continuation:** prior default task was Financial while the latest user explicitly prioritized controller repair; a stale selector can restart the wrong work even when the correct prior task is recoverable.
- **Experience abstraction/retrieval:** knowledge and past P1–P19 incidents exist, but no tested repeated-failure-to-method-transfer admission had been attached to canonical cognition before this candidate.
- **Method-choice epistemics:** unchallenged old lessons can become premature new root claims; counterexamples and scope constraints matter as much as lexical similarity.
- **Effectors/validation:** schema/CI success certifies a controlled code path, not native host interception or business/product improvement.
- **Coverage and escalation:** broad research without declared source roles, adversarial expansion and saturation evidence is often shallow; requiring literal 'every page' is unachievable and not proportional.

The selected intervention is **one bounded addition to the existing `problem_space.py` + `CognitionCase`**, not a second memory store/manager: when a cognition case reports repeated failure, check the existing `KnowledgeItem` lifecycle for analogues, compare fit and misfit to current typed evidence, and choose canonical candidate reuse, provisional adaptation or evidence-backed no-match. This does not claim the native model executed that path.

## Why old experience did not reliably transfer

- **Existence**: docs, PRs, issues and source content were recoverable. This is not an empty-memory problem.
- **Index/recognition**: older evidence is identified by project and patch rather than an owner-neutral failure-class/method-fit query; task startup naturally finds current state, but does not automatically select a *method*.
- **Admission**: until this candidate, repeated `CognitionCase` events did not have a required prior-method fit/misfit/no-match disposition. They could satisfy causal structure without proving past lessons were considered.
- **Execution**: even a promoted Python admission is only protective on a path that actually calls it; native ChatGPT invocations remain unverified.
- **Learning/feedback**: parent candidate and later observed outcome do not automatically establish that future tasks used the method. Method `usage_links` need grounded observed reuse; promoted knowledge must be retired on counterevidence.

Do NOT solve this by a separate Agent library, duplicated full cognition OS inside Financial, hundreds of standalone 'always remember' prompt rules, or a brittle exact keyword match. Do not force new method transfer on a one-off familiar case. The typed admission is triggered by `repeated_failure_count >= 2` and produces an explicit `NO_REUSABLE_METHOD` when no analogy survives.

## Evaluable alternatives

1. **No change**: existing knowledge-acquisition and cognition gates already exist, simplest, but P1–P19 and controller correction show recall→selection→action is not demonstrated; retain as negative baseline.
2. **Copy controller logic into each child**: gives local runtime code but creates revision divergence and duplicate owner semantics; rejected until actual host and direct-child traces justify an independent fallback.
3. **Append a method-transfer owner to cognition and current KnowledgeItem** (**candidate selected**): small reusable evidence adapter, objective matches P-failure recurrence. Costs: more admission metadata and risk of hallucinated reference existence; restrict status to `candidate` and require typed current-case evidence, test negative conditions.
4. **Rebuild entire system as separate MAPE-K/monitor agent**: sensor/effector reality unproved; adding another dashboard or index cannot fix native mediation. Rejected now; revisit only with a measurable new host capability.
