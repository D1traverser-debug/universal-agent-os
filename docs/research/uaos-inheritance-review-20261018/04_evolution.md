# Continuous learning and evolution study

Sources: https://asq.org/quality-resources/pdca-cycle ; https://airc.nist.gov/airmf-resources/airmf/5-sec-core/ ; current UAOS config/EVOLUTION_POLICY.json; current UAOS config/DEEP_TASK_EXECUTION_PROFILE.json.

Independent learning unit: question or failure/opportunity; primary/raw evidence and independent source roles; multiple method families; explicit refutation attempts and tradeoffs; bound applicability; validation scenario; canonical owning rule/Skill/SOP/test if change is justified; a post-promotion observation; next discovery trigger.

Current weakness: an existing EvolutionTransaction with INCIDENT/CAPABILITY_GAP/EVALUATED_KNOWLEDGE origins can persist learning AFTER a case is opened, but selecting parent UAOS without a current case does not itself guarantee new architecture or knowledge-space review. A completed task cannot masquerade as a perpetual discovery cycle.

Design challenge:
A. More permanent instruction lists: promote duplicates, overload context. Reject.
B. Require a complete raw reread of every file every turn: expensive and does not prove outcomes or unseen failures. Reject as exclusive mechanism, but preserve full inventory and ability to demand exhaustive review.
C. On each explicit controller-selection event, open/resume a review receipt for all registered repos and all critical control families, then research in independent modules and consume evidence until saturation. Use existing state/TASK_INDEX, CognitionCase, DeepTask and EvolutionTransaction as needed. Select C.

A review with missing cells stays incomplete, rather than ending with an authoritative green sign-off. If knowledge is already well validated, record a tested NO_CHANGE decision rather than adding rules.
