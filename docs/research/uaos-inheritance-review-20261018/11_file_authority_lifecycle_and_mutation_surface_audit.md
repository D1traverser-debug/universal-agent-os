## Decision: remove ambiguity before adding machinery

1. **Fix proven drift:** index stage equality, historical document authority labels. **Keep** historical documents, completed subordinate receipts and evolution evidence; deleting them would destroy lineage without eliminating authority competition.
2. **Harden destructive actual storage path:** portable snapshot create/verify/restore rejects unsafe manifest and symlink paths, verifies staged contents and reverts ordinary partial restore failures. Frozen positive/negative tests live in `tests/state/test_portable_snapshot.py`; ordinary rename-failure rollback is *not* a claim of cross-device power-loss transaction.
3. **Bind index projection to owner:** the existing `tests/integrations/test_fresh_chat_resume.py` compares each indexed task status/stage/identity/authority to its exact task source, and requires any unindexed task record to be a completed linked subordinate receipt, not a rival RUNNING/default task. No new index or registry.
4. **Remain open:** A GitHub connector may directly write a candidate branch without UAOS Python Coordinator because native host mediation is external. `protect-main` reduces direct-production risk but does not unify all writes. Security review of snapshot concurrency/symlink races and host integration of the asset gate, external object deletion, and real restoration under interruption require further verification.
5. **Stop condition:** candidate CI/negative tests + code review + PR promotion + production reread prove only **this bounded source-level reconciliation**. The comprehensive user demand ("废旧漂移混乱文件管理与写入都统一了吗") remains **NO** until write paths and active host enforcement have observed coverage, and ongoing drift detection can operate without repeated user instruction.

**Anti-bloat:** no new file database, no second authority; no deletion of valid historical evidence; no secondary progress store. Historical candidate documents get metadata/source-bound demotion, not falsified status rewrites.

## 2026-10-19 snapshot TOCTOU source repair and external deletion boundary

**Controlled fix, not complete physical mediation.** A check-then-use boundary in `src/uaos/state/snapshot.py` previously scanned symlinks and checked `Path.is_file()`, then reopened by pathname for hashing and restore staging. A concurrent replacement of an intermediate artifact directory could redirect the later read. PR [#125](https://github.com/D1traverser-debug/universal-agent-os/pull/125) protected POSIX artifact-relative paths with descriptor-relative `O_NOFOLLOW` opens, but its compound snapshot root still allowed an ancestor symlink to be followed. The root/ancestor counterexample was reproduced by independent review of PR #126; candidate PR [#128](https://github.com/D1traverser-debug/universal-agent-os/pull/128) separately addresses that path. No second state store is introduced. The two new injected-race tests verify rejection of a symlink swap after file check and before restore-stage copy. Existing roundtrip, manifest integrity and ordinary failure rollback tests remain in the suite.

**Evidence:** PR #125 head `17fecfad8ffcf883572ddbe7e3db16cd4ca47971`; CI run #700 **622 passed, 2 skipped**; live integration run #396 **success** (PostgreSQL branch **624 passed, 1 skipped**, object-store job success, OpenAI provider skipped); independent automated code review completed with no findings; merged to `main` as `b5da5747adea9aa41027997a991bc56cfbae2f3a`; `main` source reread confirmed `_open_regular_beneath` and tested paths. The earlier PR #122 was also merged and `main` has no active `docs/architecture/REPO_LAYOUT.md`.

**Method transfer:** Python `os.open(..., dir_fd=...)` provides descriptor-relative operations on POSIX; `O_NOFOLLOW` only protects the final component of each *individual* open. PR #125 opened **artifact-relative** components separately but omitted snapshot-root ancestors. PR #128 adds opening each component from the filesystem anchor with no-follow before opening the leaf; its production assurance remains pending review and promotion. Linux `openat2(2)` exposes stricter whole-path `RESOLVE_BENEATH`/`RESOLVE_NO_SYMLINKS` controls but is not required by this portable Python change. Source: https://docs.python.org/3/library/os.html and https://man7.org/linux/man-pages/man2/openat2.2.html.

**Counterexample and limits:** Independent PR #126 review confirmed that replacing the entire snapshot root with a symlink between database and artifact staging could make PR #125 accept an outside-root path. PR #128 adds deterministic root-swap/ancestor tests; do not certify its fix until independent review and production readback. Windows compatibility fallback has no POSIX directory-descriptor protection; external writers can modify the source or destination without cooperating with this API; power-loss/crash atomicity of the DB+artifact pair is not established; this repo cannot intercept native ChatGPT external connectors. Do not upgrade these to PASS using CI alone.

**External object-store deletion traced rather than assumed:** `src/uaos/state/s3_artifacts.py#delete_hash` directly calls `client.delete_object`. Its confirmed in-repo live-probe call site `src/uaos/live/object_store_probe.py#run_object_store_probe` uses a fresh SHA256 probe payload under `live-probe`, then deletes that test object and verifies absence. That is intentionally scoped test cleanup, **not evidence of unauthorized production deletion** or proof that every provider-side durable write is catalog-admitted. Production bucket permissions, retention policy, non-probe callers, and host/provider adapter enforcement remain open.
