# ChatGPT Fresh-Chat Bootstrap Pointer

UAOS repository authority remains the source of truth. ChatGPT Custom Instructions are bootstrap-only and non-authoritative; activation-only in function. They provide a stable native-session interrupt into the installed `uaos-controller-runtime` Skill; they do not own cognition, evolution, business rules, task state, or mutation authority.

## Recommended Custom Instructions

Use this single compact pointer. It remains within the repository's 1,500-character portability budget:

> For every request, independently assess the minimum sufficient investigation, deliberation, verification and execution for the underlying goal. Keep simple tasks lightweight. An explicit depth request is a mandatory escalation signal, not the only trigger. The user is not the classifier.
>
> For continue/inherit/resume, persistent Agent work, or UAOS, bootstrap from `D1traverser-debug/universal-agent-os@main:ENTRYPOINT.md` and `CURRENT_SYSTEM.json`. Resolve current authority semantically; never use chat memory, prior assistant conclusions, historical branches or retired files as authority.
>
> After UAOS/domain selection, load `config/NATIVE_SESSION_RUNTIME_PROFILE.json`. For corrections, failures, repeats, contradictions, knowledge gaps, architecture/control-plane issues or suspected local patches, use installed `uaos-controller-runtime` to dispatch current UAOS cognition/evolution/closure. Treat user/model/prior-assistant/expert claims, existing code and the first convenient fix as hypotheses until evidence supports them. Repeated/systemic repairs must cover the failure class and generalize; local closure requires evidence the class is local.
>
> If authorized work can continue without missing user input/approval/authorization/safety choice, continue; never use `next` or another no-op user message as the workflow clock. Use included ChatGPT capabilities, Skills/Plugins, GitHub and CI by default; no paid API/Codex/credits unless requested. Repository authority overrides this pointer.

Do not paste the full UAOS policy, the five-stage cognition semantics, Deep Task evidence dimensions, evolution lifecycle, or systemic-repair field list into Custom Instructions. Duplicating those semantics creates drift and a second stale source of behavior.

## Runtime Skill boundary

`skills/uaos-controller-runtime/SKILL.md` is the installable native ChatGPT dispatcher source. It is deliberately non-authoritative:

- metadata broadens discovery for persistent-Agent work, corrections, failures, repeated/systemic problems, architecture/control-plane issues and suspected local patches;
- on activation it rereads current GitHub production authority and the compiled native runtime projection;
- detailed cognition/evolution/closure semantics remain owned by the canonical repository policies and executable gates;
- the Skill does not create a second cognition state machine, controller, evolution lifecycle, or task store.

The account-level manual action is limited to installing the produced Skill bundle and replacing Custom Instructions with the exact recommended pointer after the repository change is promoted.

## Why this split

- Custom Instructions are persistent native-session guidance, so they are the narrow always-present activation surface available without an extra API/runtime.
- Skill discovery uses its name/description and loads the full workflow when relevant; the pointer explicitly names the Skill for selected-context problem signals rather than relying on relevance discovery alone.
- `config/NATIVE_SESSION_RUNTIME_PROFILE.json` remains a generated read model over current canonical Session/Deliberation/Host authority, reducing per-turn policy assembly.
- GitHub remains durable authority for code, state, evidence, tests and evolution history.
- The current problem-closure executable, not the Skill text, decides whether a systemic repair has sufficient failure-class/generalization evidence.

## Enforcement boundary

Custom Instructions, Skills and the compiled native profile improve activation and execution consistency, but they do not prove that the ChatGPT product runs a UAOS pre-send validator before every response. They also do not prove a repository-controlled pre-tool hook or non-bypassable semantic-signal injector. Hosts controlled by UAOS should use `src/uaos/runtime/finalization.py`; the OpenAI Agents SDK adapter can attach that gate as a blocking output guardrail through `build_uaos_output_guardrail`.

For native ChatGPT, the strongest accurate claim remains behavioral: the account pointer directs selected sessions to current authority and the installed runtime dispatcher. It is not a repository-controlled physical complete-mediation guarantee.
